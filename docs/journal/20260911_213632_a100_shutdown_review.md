迁移建议这样做：

1. **选择 A100 40GB 整卡作为起点。** 当前双模型运行的显存采样峰值约 29.49 GiB，vLLM 支持 A100；我们这套工程仍需在新机器上实际验收。[vLLM 硬件要求](https://docs.vllm.ai/en/v0.19.1/getting_started/installation/gpu/)
2. **如果仍在 AutoDL 同地区，使用“克隆实例”，勾选复制数据盘，再选择 A100。** 系统盘保存 GPU 环境，数据盘保存项目、权重和结果；两部分都要迁移。[官方迁移步骤](https://www.autodl.com/docs/migrate_instance_2/)
3. **如果换云平台，按仓库脚本重建环境。** 准备兼容的 NVIDIA 驱动、Python 3.12、uv 和 Icarus，使用 `scripts/setup_cuda.sh` 安装锁定依赖，另行复制权重、校验清单和实验产物。不要直接跨机器复制虚拟环境。
4. **新机器先跑 pytest 和 3 道 testcase，再跑完整 156 题。** 保持模型版本、算法和依赖版本一致，方便比较。全量入口仍是 `./run.sh --suite verilogeval-v2`。

这里有个具体细节：服务器的 `.venv-vllm` 指向系统盘上的 `/root/qiansai-envs/vllm-0.19.1`。**只复制项目文件夹，会漏掉这个环境。** 目前自有 Docker 镜像尚未构建验收，迁 A100 不必以 Docker 化为前提。

另外，当前每个模型服务配置 `0.45` 的显存比例。换更大显存的卡后，不能沿用比例就认为仍满足 32 GB 限制，需要调整分配并重新测量。[vLLM 显存配置](https://docs.vllm.ai/en/v0.19.1/configuration/optimization/)

“关掉服务器”要区分几种操作：

| 操作 | 影响 |
|---|---|
| 关闭 SSH／浏览器 | 用 nohup 启动的后台任务可以继续；实例仍在运行、计费。 |
| AutoDL 普通关机 | 所有进程停止，内存和显存清空；系统盘、数据盘按平台规则保留。重开后重新启动模型。 |
| 重置／更换系统镜像 | 系统盘环境被替换，数据盘保留；GPU 环境可能需要恢复。 |
| 释放／删除实例 | 实例的系统盘和数据盘被清除。 |

AutoDL 当前规定：**连续关机 15 天会自动释放实例并清除数据**。保存的系统镜像也不包含数据盘，因此权重和结果需要另存。[数据保留规则](https://www.autodl.com/docs/instance_data/)、[镜像说明](https://www.autodl.com/docs/image/)

按量实例关机后停止算力计费，但不保留 GPU 名额，重开时可能没有空闲卡；包时租期和付费存储另计。[计费与资源规则](https://www.autodl.com/docs/price/)

**我的建议：短期暂停就普通关机；长期停用或准备释放，先补齐“私有系统镜像＋独立数据备份”。** 目前代码和实验结果已有异机副本，两份权重和 GPU 环境尚未由我们做独立备份。迁移时保留旧实例，等 A100 验收、备份核对通过后再释放。
