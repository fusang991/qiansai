## 助手最终回复

**可以直接 `git clone` 获取工程，但 clone 完还需要安装环境、准备模型权重，才能运行。**

目前三处分别保存这些内容：

| 内容 | 本地电脑 | 当前服务器 | GitHub / clone 能否获得 |
|---|---|---|---|
| 我们的代码、脚本、配置、文档 | 有 | 有 | 能 |
| ChipMATE 上游代码、156 题原始数据集 | 有 | 有 | 能，需要同时拉取子模块 |
| 转换后的题目数据 | 有 | 有 | 不直接保存，安装脚本会重新生成 |
| 工作流 Python 环境 `.venv` | 有 | 有 | 不保存，新机器重新安装 |
| GPU 推理环境：vLLM、PyTorch 等 | 没有项目 GPU 环境 | 已安装 | 不保存安装好的环境，但保存了依赖版本和安装脚本 |
| 两个 4B 模型的实际权重，合计约 18 GB | **没有** | **有** | **没有**，只保存版本和校验信息 |
| 完整实验结果 `runs/` | 已备份全量实验及对照结果 | 有原始结果 | 不保存完整产物，文档里有结果说明 |

本地工程在 `/home/young/autodl/qiansai`，服务器工程在 `/root/autodl-tmp/qiansai`。

**在一台全新的 NVIDIA 服务器上，按下面的顺序准备。** 前提是机器能访问仓库，并已具备可用的 NVIDIA 驱动、Python 3.12、uv 0.9.18、Icarus Verilog 和编译工具。

```bash
# 1. 获取工程、ChipMATE 和原始数据集
git clone --recurse-submodules https://github.com/fusang991/qiansai.git
cd qiansai

# 2. 安装两个 Python 环境、生成题目数据，并运行 pytest
bash scripts/setup_cuda.sh

# 3. 登录具有两份模型访问权限的 Hugging Face 账号，下载权重
.venv/bin/hf auth login
.venv/bin/python scripts/fetch_models.py

# 4. 先验证三道已经在旧服务器通过的题
./run.sh --case Prob001_zero --case Prob007_wire --case Prob034_dff8

# 5. 再运行完整 156 题
./run.sh --suite verilogeval-v2
```

第 3 步也可以改为：**把旧服务器的整个 `model/weights/` 目录复制到新工程的同名位置，并核对校验清单**，这样不用重新下载。要连同模型配置、分词器和清单一起复制。

旧的 `runs/` 只在需要查看历史实验时另行复制，**运行新 testcase 不依赖旧结果**。旧服务器的 Python 环境也不必搬，安装脚本会在新机器重新创建。

目前支持的是“**首次准备环境和权重，之后一条命令跑 testcase**”。仅执行 `git clone` 就立刻跑模型的全自动部署，还没有做到。
